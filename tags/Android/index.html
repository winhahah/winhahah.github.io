安卓应用克隆漏洞

现在其他手机上重现应用的状态的问题应用克隆漏洞主要是指通过跨域读取应用的本地沙盒数据(/data/data/packagename下的文件)，从而实现在其他手机上重现应用的状态的问题。

漏洞利用条件

  1. webview
  2. 开启的file域的跨域访问

攻击者可以让应用加载指定的网页文件。

攻击流程：

该漏洞主要利用了Android系统WebView控件的同源策略漏洞来进行攻击，Android应用内部分可导出的Activity组件中，WebView允许通过file url对http域进行访问，并且并未对file域的路径进行严格校验所导致的。
该漏洞会打破Android应用的沙箱隔离机制，即A应用可以通过B应用导出的Activity让B应用加载一个恶意file协议的url，从而获取B应用的内部私有文件。

案例

  1. 创建钓鱼链接
  1. 攻击poc：cloneapp.html
  1. 打开带有漏洞的应用，并点击该链接。
  2. 可以在监听的http://192.168.42.1:9999收到转发过来的file:///data/data/ddns.android.vuls/files/token.txt内容。

DeepLink加载任意URL

DeepLink是一种允许应用程序通过URL直接响应特定页面或功能的技术。这是通过操作系统和应用程序之间的一种约定来实现的。

DeepLink结构：

部分 说明 示例
scheme 协议头，自定义或 https myapp / https
host 域名或逻辑模块 shop.example.com
port 端口（可选） 8080
path 页面/资源路径，标识“去哪” /product/123
query 业务参数，标识“带什么状态” from=share&coupon=10
fragment 锚点/子视图（可选） review

在 Android 中，当安装一个应用程序时，该应用程序的 manifest 文件（AndroidManifest.xml）会注册到系统中。这个文件包含了该应用程序的所有组件信息，包括 activities、services、broadcast、receivers 等。对于 deep link，开发者可以在 manifest 文件中定义一个或多个 intent filters，这些 intent filters 定义了哪些 URL 可以启动哪些 activities

当用户点击一个符合某个应用程序 intent filter 规则的 URL 时，Android 系统就会启动该应用程序的对应 activity。具体的规则是通过 intent filter 中的 data 元素来定义的，这个元素可以指定 URL 的 scheme、host、path 等信息。如果 URL 符合这些规则，那么就会启动对应的 activity。

Android Deep Link（深层链接）是一种特殊的链接协议，主要用于在应用程序之间导航和交互，使用 Deep Link 可以从一个APP跳转到另一个APP中相应的页面，实现APP间的无缝跳转。

查找Deep Link

在Android系统中，应用需要在AndroidManifest.xml文件中声明它们能处理的Deep Link。
因此，我们可以通过使用jadx等反编译工具对目标APK进行反编译，在反编译后的AndroidManifest.xml文件中搜索关键字：”android:scheme”

一般搜索结果所在的data标签部分，就包括了Deep Link Url所需的必要组成部分：

  • scheme: oversecured,
  • host: ovaa
    转换成url就是：oversecured://ovaa

    dex加固、so加固、抓包检测、Hook检测、root检测

Frida17代码补全功能 Nodejs+VSCode

Frida17更新后，代码补全功能变得麻烦了。

nodejs和vscode没什么好说的，直接一路安装，自己再装上几个顺手的插件即可。

frida-node需要注意一下版本，本质是Frida 的Node.js 绑定

另外，看了下资料，在frida17中，出现了架构变化

  • Frida ≤16：Java 是 GumJS 全局变量，脚本里直接写 Java.perform 能跑也能猜类型
  • Frida 17+：Java / ObjC / Swift 桥被拆出去，不默认注入
    • 运行时要用必须：import Java from "frida-java-bridge"
    • 但 frida CLI/REPL 为了兼容老脚本，会临时给你挂一下全局 Java，所以能跑但编辑器不知道类型
      自动补全功能无了。所以要稍微配置一下
  1. 安装两个关键插件

npm install 默认把包写进 package.json 的 dependencies；加 –save-dev（简写 -D）就写进 devDependencies。一个是生产环境，一个是开发环境。区别如下：

dependencies devDependencies
含义 运行时需要 只在开发/构建时需要
npm install（生产） 装 装（默认）
npm install --production / --omit=dev 装 不装​
别人 npm i 你的包 装 装
作为库被依赖时 装 不装​

判断标准:

frida-gum只含 .d.ts，不含运行时代码，作用是写 Agent（TS）时有补全、类型检查。不提供Java.use等。
是GumJS 里的Java/ART/Dalvik 桥接库，被注入到目标 App 的 Agent 脚本里，提供Java.perform / Java.use / Java.choose / Java.cast。

功能区别：

  • frida-gum：是 Frida 注入到目标进程后的原生插桩引擎（C 层 + GumJS 全局 API）。
    Interceptor / Memory / Module / Process / NativeFunction 这些全局直接可用，不需要你 import 任何包。
  • @types/frida-gum：只是 TS 类型声明，编译完就消失，运行时完全不需要。
  • frida-java-bridge：只在你要操作Java/Kotlin 层时才需要（Frida 17+ 要显式装、显式 import）。

算法分析流程

  1. 抓包分析是否有需要逆向的加密字段
  2. 查壳分析是否有加固
  3. 查看界面元素，看是否是原生开发的app，因为不同形式app分析方法不一样
  4. 传统关键代码定位方法：1、查看控件id，然后寻找绑定方法。2、抓包看到URL地址，搜索字符串，搜不到从前往后依次去掉一部分继续搜索。3、搜索加密的函数Encrypt，数量比较多的话在前面后者后面加上单引号或双引号，如Encrypt”
  5. 关键代码快速定位
    Hook常用系统函数，如果app有调用就打印函数栈
  6. 逆向分析不是完全静态分析明白了才去hook，实际上是边分析边hook、不断怀疑、不断验证、不断推翻、不断找新关键函数的过程

Andrid开发方式判断

不同的开发方式有着不同的逆向方法了。

原生方式开发的app，使用Java和C开发，加密用的是Java和C。H5的app，使用webview控件加载网页，加密用的是JS。原生逆向分析分析的是dex文件，如果是H5开发，可能就没有dex文件。这一点对逆向的影响很大，所以要区别一下。

App架构类型：

  1. H5架构(Web App)
    基于Web技术(HTML/CSS/JS)开发
    运行在App内的WebView组件中
    本质上就是一个网页的封装
  2. Android原生架构(Native App)
    基于Android平台原生语言开发(Java/Kotlin + Android SDK)
    Android SDK(软件开发工具包)
  3. Hybrid App(H5 + Android原生混编)
    在原生容器(如 WebView)里加载H5页面
    同时用原生代码实现关键功能(如 导航栏、支付)
  4. 跨平台原生架构(如 Flutter、React Native)
    基于第三方框架(如 Flutter、React Native)进行开发
    编写一次代码
    可以同时在Android和iOS上运行
架构类型 开发语言/技术 性能表现 跨平台能力 典型代表
H5架构 HTML/CSS/JS 较低 极强（WebView） 营销活动页
Android原生 Java/Kotlin 极高 无（仅Android） 大型游戏
Hybrid混合 H5 + 原生 中等 较强 电商/资讯App
跨平台原生 Flutter/RN 高（近原生） 强（双端） 多数商业App
