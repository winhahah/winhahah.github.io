SSL Pinning机制与过检测

SSL Pinning（证书固定 / 公钥固定）是一种在客户端里“写死”（也可以是自身写死+服务器返回的动态列表）服务器身份的 TLS 增强机制：不只依赖系统信任库（CA 体系），而是额外校验“服务器证书/公钥是不是我预先认识的那一个”。

类型介绍

类型 Pin 的内容 优点 缺点
整证固定​ 叶子证书 DER 哈希 最严格 证书一续签就挂，必须发版
公钥固定（推荐）​ SPKI 的 SHA-256（Base64） 续签同密钥不破，运维友好 实现稍复杂
CA/中间证固定​ 中间 CA 公钥 最稳，适合 CDN 信任范围变大，安全性略降

1. 整证固定（Leaf Certificate Pinning）

原理：客户端保存服务器叶子证书的 DER 编码，计算 SHA-256 哈希，每次 TLS 握手时比对。

Android OkHttp 实现：

优点：最严格，攻击者完全无法伪造。
缺点：证书一续签（哪怕只是重新签发，密钥没换），所有老版本 APP 全部失效。

2. 公钥固定（SPKI Pinning，推荐）

原理：Pin 的不是证书本身，而是证书里的公钥（Subject Public Key Info）。
证书可以换，但只要公钥不变，Pinning 依然有效。

3. 中间 CA 固定（CA Pinning）

原理：Pin 证书链里的中间 CA 公钥。只要中间 CA 不变，叶子证书随便换。
适用场景：
- 使用云厂商 CDN（如 AWS、Cloudflare）
- 证书频繁自动续签（Let’s Encrypt 90 天）

实现：
- 从证书链里取第 1 个或第 2 个证书的 SPKI
- 通常 Pin 中间 CA 的 SPKI，因为叶子证书会频繁换

脚本入口：Java.perform(function() { … }) ，在 Java 层运行时注入，Hook 各种 SSL 校验点。

  1. 自定义 TrustManager并实例化：注册一个“接受一切证书”的 TrustManager。checkServerTrusted 空实现：服务端证书永远通过校验。getAcceptedIssuers 返回空数组：不信任任何 CA，但也无所谓，因为校验函数什么都不做。getAcceptedIssuers：返回空数组。

Magisk和LSPosed

Magisk是Android 系统级 Root 工具，LSPosed是Magisk的一个模块。

Magisk

核心特点是 系统分区无修改，因此也被称为“系统less Root”。

  1. 传统 Root（如 SuperSU）：
    • 直接修改 /system 分区文件（如替换 su 二进制）
    • 容易触发系统完整性校验（如 SafetyNet）
  2. Magisk：
    • 在启动阶段通过 ramdisk 补丁* 注入一个 magiskd 守护进程
    • 使用 OverlayFS 挂载机制，在 /system 之上叠加一层虚拟文件系统
    • 实际系统分区保持原样，所有修改都在内存中完成

Magisk 模块示例

  • MagiskHide：隐藏 root 状态（已被 Zygisk 取代）
  • Systemless Hosts：修改 hosts 文件屏蔽广告
  • ViPER4Android：音效增强
  • LSPosed：Xposed 框架的 Magisk 模块版（用于应用 Hook）

与frida关系，

LSPosed

LSPosed 可以理解为：现代版 Xposed 框架，跑在 Magisk（Zygisk）里的“应用/系统行为修改器”。
原版XPosed很老了，到现在只有一些社区维护，用新版本比较好。

不修改 APK、不修改系统分区，在运行时 Hook Java 方法，改变 App 和系统行为。和frida的区别如下：

  • Frida：运行时动态注入，适合临时调试、逆向分析
  • Xposed/LSPosed：常驻框架，重启生效，适合做“持久化修改”（去广告、假数据、反检测）
工具 干的事
Magisk 提供 root + 系统层挂载能力
LSPosed 在 root 基础上，做“应用内方法级 Hook”

这里对运行原理进行一个说明：
Zygote 是 Android 系统启动时创建的第一个 Java 进程，所有 App 进程都是由它“分裂”出来的。

Zygisk（Magisk 的注入机制）
Zygisk 是 Magisk 的一个功能模块，作用是在 Zygote 启动时“偷偷注入”代码。

入口寻找

打开AndroidManifest.xml，搜索android.intent.action.MAIN或者LAUNCHER，找到后，向上看，找到包含这段代码的 <activity> 标签，这个 Activity 就是入口类。
<activity> 是 Android 清单文件中用来声明一个 Activity 组件的标签。
入口 Activity 的判断标准是：同时包含 MAIN 和 LAUNCHER 的 <intent-filter>
在一些文件中，可能会有多个入口。但是标签是<activity-alias>，这个标签是为已有的 Activity 创建一个“别名”或“快捷方式”。标签下还有个android:enabled=”false”，如果是false表示这个入口被关闭。

安卓常用目录介绍

安卓常用目录介绍

data/data 目录存放用户apk数据的目录，每个apk都有自己的目录，以包名命名就是在data/data/目录下，会产生一个跟 Package一样的目录这是一个私有目录，app只能访问各自的目录，除非root权限
data/app 目录用户安装的app存放在这个目录下
data/local/tmp 临时目录，权限比较大
system/app 目录存放系统自带的app
system/lib 目录、system/lib64 存放app用到so文件
system/bin 目录存放 shell命令
system/framework Android系统所用到框架，如一些jar 文件，XposedBridge.jar

sd卡目录不管手机有没有存储卡都会有这个目录，app操作sd卡目录需要申请权限
/sdcard ->/storage/self/primary
/mnt/sdcard
/storage/emulated/0
