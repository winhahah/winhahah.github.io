DeepLink加载任意URL

DeepLink是一种允许应用程序通过URL直接响应特定页面或功能的技术。这是通过操作系统和应用程序之间的一种约定来实现的。

DeepLink结构：

部分 说明 示例
scheme 协议头，自定义或 https myapp / https
host 域名或逻辑模块 shop.example.com
port 端口（可选） 8080
path 页面/资源路径，标识“去哪” /product/123
query 业务参数，标识“带什么状态” from=share&coupon=10
fragment 锚点/子视图（可选） review

在 Android 中，当安装一个应用程序时，该应用程序的 manifest 文件（AndroidManifest.xml）会注册到系统中。这个文件包含了该应用程序的所有组件信息，包括 activities、services、broadcast、receivers 等。对于 deep link，开发者可以在 manifest 文件中定义一个或多个 intent filters，这些 intent filters 定义了哪些 URL 可以启动哪些 activities

当用户点击一个符合某个应用程序 intent filter 规则的 URL 时，Android 系统就会启动该应用程序的对应 activity。具体的规则是通过 intent filter 中的 data 元素来定义的，这个元素可以指定 URL 的 scheme、host、path 等信息。如果 URL 符合这些规则，那么就会启动对应的 activity。

Android Deep Link（深层链接）是一种特殊的链接协议，主要用于在应用程序之间导航和交互，使用 Deep Link 可以从一个APP跳转到另一个APP中相应的页面，实现APP间的无缝跳转。

查找Deep Link

在Android系统中，应用需要在AndroidManifest.xml文件中声明它们能处理的Deep Link。
因此，我们可以通过使用jadx等反编译工具对目标APK进行反编译，在反编译后的AndroidManifest.xml文件中搜索关键字：”android:scheme”

  • scheme: oversecured,
  • host: ovaa
    转换成url就是：oversecured://ovaa

SSL Pinning机制与过检测

SSL Pinning（证书固定 / 公钥固定）是一种在客户端里“写死”（也可以是自身写死+服务器返回的动态列表）服务器身份的 TLS 增强机制：不只依赖系统信任库（CA 体系），而是额外校验“服务器证书/公钥是不是我预先认识的那一个”。

类型介绍

类型 Pin 的内容 优点 缺点
整证固定​ 叶子证书 DER 哈希 最严格 证书一续签就挂，必须发版
公钥固定（推荐）​ SPKI 的 SHA-256（Base64） 续签同密钥不破，运维友好 实现稍复杂
CA/中间证固定​ 中间 CA 公钥 最稳，适合 CDN 信任范围变大，安全性略降

1. 整证固定（Leaf Certificate Pinning）

原理：客户端保存服务器叶子证书的 DER 编码，计算 SHA-256 哈希，每次 TLS 握手时比对。

Android OkHttp 实现：

优点：最严格，攻击者完全无法伪造。
缺点：证书一续签（哪怕只是重新签发，密钥没换），所有老版本 APP 全部失效。

2. 公钥固定（SPKI Pinning，推荐）

原理：Pin 的不是证书本身，而是证书里的公钥（Subject Public Key Info）。
证书可以换，但只要公钥不变，Pinning 依然有效。

3. 中间 CA 固定（CA Pinning）

原理：Pin 证书链里的中间 CA 公钥。只要中间 CA 不变，叶子证书随便换。
适用场景：
- 使用云厂商 CDN（如 AWS、Cloudflare）
- 证书频繁自动续签（Let’s Encrypt 90 天）

实现：
- 从证书链里取第 1 个或第 2 个证书的 SPKI
- 通常 Pin 中间 CA 的 SPKI，因为叶子证书会频繁换

  1. 自定义 TrustManager并实例化：注册一个“接受一切证书”的 TrustManager。checkServerTrusted 空实现：服务端证书永远通过校验。getAcceptedIssuers 返回空数组：不信任任何 CA，但也无所谓，因为校验函数什么都不做。getAcceptedIssuers：返回空数组。

    7. httpclientandroidlib（老式 Apache）：Hook AbstractVerifier.verify()：让它直接返回
    8. Android 7.0+ TrustManagerImpl：Hook verifyChain()：直接返回未校验的证书链；绕过 network_security_config 的 pin-set
    9. OpenSSLSocketImpl（底层 TLS）：Hook verifyCertificateChain()：让它直接返回
    10. TrustKit（第三方 Pinning 库）：Hook OkHostnameVerifier.verify()：让它返回 true
    11. Cronet（Chromium 网络栈：Hook addPublicKeyPins()：让它不添加任何 Pin ；Hook enablePublicKeyPinningBypass…()：强制开启本地信任锚点绕过 。

详细介绍下

  1. assets/
    • 应用打包时原样放入的“原始文件”
    • 不会生成 R.id/... 资源 ID
    • 运行时通过 AssetManager / getAssets().open("xxx") 读取
    • 常见内容：
      • 配置文件、JSON、离线地图、模型文件、字体、网页资源、加密密钥/脚本等
    • 与 res/ 区别：res 会被 aapt2 编译并分配资源 ID，assets 保持原样
  2. lib/

    • 存放 Native 动态链接库 .so

    • 通常按 CPU 架构分子目录，例如：

    • 通过 JNI 调用，比如音视频、加解密、网络加速、安全校验、游戏引擎等

    • 运行时会由系统按设备 ABI 选择加载。ABI简单理解是，系统的驱动版本和底层架构。

    • 也是包体积“大头”之一

  3. META-INF/
    • APK 签名信息所在目录（APK 必须签名才能安装）
    • 常见文件：
      • MANIFEST.MF：各文件摘要（SHA/SHA256）
      • CERT.SF：对 MANIFEST 的签名相关文件
      • CERT.RSA / CERT.DSA：签名证书/公钥信息
    • 用于：
      • 安装校验完整性
      • 校验是否篡改
      • 判断“是否同签名”（覆盖安装、系统权限、共享 UID 等）
    • 重打包/改文件后签名会变，需重新签名
  4. okhttp3/
    • 不是 Android 强制标准目录，通常是 **OkHttp（Square/Android 常用网络库）**​ 打包带出的资源/配置
    • 可能包含：
      • 内置证书/配置
      • 网络拦截器相关资源
      • Kotlin/Java 库资源（有些库会往根目录放东西）
    • 说明该 App 使用 OkHttp 做 HTTP/HTTPS 请求（很常见）
  5. res/
    • Android 标准资源目录
    • 会被编译进资源表，通过 R.xxx.xxx 或 Resources.getXXX() 访问
    • 常见子目录：

    不同后缀（如 -hdpi/-xhdpi/-xxhdpi/-zh-rCN）表示适配不同屏幕/语言

  6. AndroidManifest.xml
    • 应用清单文件（核心）
    • 包含：
      • 包名（如 package="com.tencent.android.qqdownloader"）
      • application 节点（入口、主题、允许备份、硬件加速等）
      • 四大组件：
        • activity
        • service
        • receiver
        • provider
      • 权限声明：
        • uses-permission（要什么权限）
        • uses-feature（需要相机/定位等特性）
      • SDK 版本：
        • minSdkVersion
        • targetSdkVersion
        • compileSdkVersion（有时在构建信息里）
      • 安装位置、支持屏幕等
    • 注意：APK 里通常是 二进制 XML（AXML），不是直接可读文本；你这里显示用 Edge 打开，可能是反编译工具已转成文本/或你用工具查看
  7. classes.dex
  8. classes2.dex / classes3.dex / classes4.dex / classes5.dex
    • .dex = Dalvik/ART 可执行字节码文件
    • 由 Java/Kotlin 源码经 javac → d8/r8/dx 转换而来
    • App 逻辑基本都在这里：
      • 页面逻辑
      • 网络请求
      • 业务规则
      • 加解密
      • 插件/下载逻辑等
    • 为什么有多个 dex：
      • Android 单个 Dex 方法引用上限 65536（64K）
      • 超过就开启 Multidex，拆成 classes.dex、classes2.dex…
      • 大厂/大型 App（如应用宝）很常见
    • 分析工具：
      • jadx（反编译成 Java/Kotlin 近似代码）
      • apktool（反编译/回编译资源与 smali）
      • smali/baksmali（看/改底层字节码）
      • Android Studio / jd-gui 等
  9. jacoco-agent.properties
    • **JaCoCo（Java Code Coverage）**​ 代码覆盖率工具相关配置
    • 用于测试时统计“哪些代码被执行过”
    • 正常发布版一般不该带，常见是：
      • 测试包/内部构建
      • 开启覆盖率采集
      • 反编译/解包看到残留
    • 可能配置：
      • agent 输出路径
      • 包含/排除类规则
      • 覆盖率 dump 方式
  10. resources.arsc
    • 编译后的资源索引表（二进制资源表）
    • 作用：把代码里的资源 ID（如 0x7f0...）映射到：
      • 字符串值
      • 布局/图片路径
      • 主题/样式
      • 多语言/多密度对应资源
    • 由 aapt/aapt2 生成
    • 改资源后通常要重新生成/通过 apktool 处理
    • 与 res/ 配合理解：
      res/ 是“资源源文件/编译后片段”，resources.arsc 是“查表索引”
