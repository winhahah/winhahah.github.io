git 及 github 使用指南

这就不说多重要了吧，给朋友写的。

git

  • 设置用户名: git config --global user.name xxx
  • 设置邮箱: git config --global user.email xxx@xxx.com
  • 查看用户名:git config user.name
  • 查看邮箱: git config user.name

私有仓库 ssh 克隆

  • 步骤 1: 生成 SSH 密钥
    • 打开git终端，输入ssh-keygen -t ed25519 -C "your_email@example.com"
      • ​​说明​​:
        -t ed25519: 使用更安全的 Ed25519 算法（兼容性要求高时可用 -t rsa -b 4096）。
        -C “注释”: 标识密钥用途（如邮箱或设备名）。
      • ​交互提示​​:
        • 按回车使用默认路径（~/.ssh/id_ed25519）。
        • 可选设置密钥密码（增强安全性，但每次使用需输入）。
      • 结果:
        • id_ed25519: 私钥（需保密）。
        • id_ed25519.pub: 公钥（需添加到 GitHub）。
  • 步骤 2: 添加到 GitHub 账户​​
    • 登录 GitHub → Settings → SSH and GPG Keys → New SSH Key。
      • Title: 标识设备（如 My Laptop）。
      • Key type: 保持默认 Authentication Key。
      • Key: 粘贴复制的公钥内容。
      • 点击 Add SSH Key。
  • 步骤 3: 测试 SSH 连接​: ssh -T git@github.com
    • 成功响应​​：
  • 如果遇到提示输入密钥密码​：1、临时缓存密码: ssh-add ~/.ssh/id_ed25519（将指定的 SSH 私钥添加到 ssh-agent 的会话中，默认仅对当前终端生效。）。2、移除密码（不安全）: ssh-keygen -p -f ~/.ssh/id_ed25519
  • 步骤 4: 获取仓库 SSH 地址​
    • 在 GitHub 仓库页面 → ​​Code​​ → ​​SSH​​，复制地址（如 git@github.com:username/repo.git）。
  • 步骤 5: 执行克隆​
    • git clone git@github.com:username/repo.git

git 操作

  • 测试 SSH 连接
    ssh -T git@github.com
  • git 初始化仓库：
    1. git clone: 克隆已有仓库
    2. git init: 初始化新仓库
  • 和 .git 同目录的是工作区。
  • 提交(commit)代码到本地仓库，仓库就是工作区下面的.git 文件夹。
    1. git add .: 将工作区的文件都变成准备提交的状态。
    2. git add main.py: 将 main.py 加入即将提交的文件。
    3. git commit -m "提交说明": 提交到本地仓库。提交成功后，git 会将源代码以数据库形式存储到仓库中。
    • git add 添加到暂存区(index 或 stage)，git commit 提交到本地的仓库。
  • 查看历史提交记录
    git log: 查看提交的历史记录。
  • git 回滚
    git checkout HEAD main.py: 将最后一次提交中的 main.py 复制到工作区(会覆盖)。
  • git 创建新分支
    git checkout -b <新分支名> [基于的起点]: Git 中用于 ​​创建并切换到一个新分支​​的快捷命令，是下面两条指令的组合。[基于的起点]​​（可选）：新分支的起点（默认基于当前所在分支的最新提交）。
    git branch 新分支名: 创建分支
    git checkout 分支名: 切换到该分支
  • git 查看工作区文件修改
    git diff
  • git 推送到远端仓库
    git push <远程名称> <本地分支名>:<远程分支名>: 如果省略 :<远程分支名>，默认远程分支与本地分支同名。
    git push -f <远程名称> <本地分支名>:<远程分支名>: -f 的作用是 force，强行 push。
    origin​​: 是一个默认的 ​​远程仓库别名（remote name）​​，它指向你克隆（git clone）的原始远程仓库地址。
  • git 拉取远端仓库到本地仓库
    git pull <远程名称> <远程分支名>: 从 origin 的 main 分支拉取并合并​。​合并的目标始终是当前本地分支​​，与分支名称是否相同无关。
  • git 删除本地分支
    git branch -D 分支名: 删除分支
  • git 合并分支
    git rebase main: ​​将当前分支的提交“重新播放”到 main 分支的最新提交之上​​。把我的修改先放到一边，然后把 main 最新的修改拿过来，接着在最新修改的基础上，尝试把我的 commit 弄进去**。这个过程中可能会出现 rebase conflict ，这个时候需要手动的选择到底需要那一段代码。**这样就相当于在最新的 main 分支上做了代码修改。

github

github 工作流程

  • github 上有个仓库，只有一个 main 分支，只有一个文件 Init。这个远端的仓库，叫做 remote。
  • 当想要修改的时候，需要使用 git clone 将项目克隆到本地仓库(.git文件夹，local)，此时我们的硬盘(或者叫工作区,disk)也会同步一份代码。
  • 修改之前，先使用git checkout -b my-feature建立新的 my-feature 分支(branch)并选中，然后往这上面提交代码。
  • 接下来就是常规的修改代码。修改完成后，可以使用git diff查看工作区的文件和本地 git 保存的文件区别。
  • 使用 git add <changed_file>将修改后的文件放入暂存区，输入git commit -m "提交说明"提交文件。这个时候本地仓库就新增一个 commit。
  • 现在需要将本地仓库的内容提交到 github 中，使用git push origin my-feature。完成后 github 就会多出一个 my-feature 分支。
  • 这个时候，可能 main 分支已经有了新的更新，我们需要测试一下经过我们修改的 my-feature 在新的这个 update 更新之下是否能正常运行。所以我们需要将 main 分支的更新同步到 my-feature 这个分支中。
  • 为了做到这个，首先需要更新本地仓库的 main 分支。使用 git checkout main切换到 main 分支中，**这时我们硬盘里的代码就是 main 初始时的状态，而不是修改后的了。**在这之后，执行 git pull origin main 将远端仓库的 main 分支同步到本地仓库的 main 中，这个时候远端仓库中新修改的文件已经到了本地仓库和工作区了。
  • 回到 my-feature 分支，执行 git checkout my-feature。然后在当前分支同步 main 分支的代码改变，执行git rebase main：把我的修改先放到一边，然后把 main 最新的修改拿过来，接着在最新修改的基础上，尝试把我的 commit 弄进去。这个过程中可能会出现 rebase conflict ，**这个时候需要手动的选择到底需要那一段代码。**这样就相当于在最新的 main 分支上做了代码修改，这也是为什么使用 rebase 而不是 merge 的原因。修改完成后，执行 git push -f origin my-feature。-f 的作用是 force，强行 push。
  • 这个时候，我们需要将我们更新的代码合并到 main 分支中，这个过程叫做 pull request(PR)，主分支是项目的，而不是个人的。项目负责人审查完代码以后，一般情况用 quash and merge。意思是**将当前分支上的所有改变，合并成一个改变，并将这个 commit 放到 main 中。**主分支上的改变尽可能要少而且能正常运行。
  • 合并完成后，一般情况下会将 my-feature这个分支删除掉。github 上有个按钮，就是 delete branch。远程仓库删除后，本地仓库还有。这个时候，我们首先要切换到 main 分支中，然后执行 git branch -D my-feature，将本地仓库的 my-feature 分支删除。最后 git pull origin main将远程仓库的 main 分支拉到本地仓库中。
