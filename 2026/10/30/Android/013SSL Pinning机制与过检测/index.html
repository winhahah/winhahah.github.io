SSL Pinning机制与过检测

SSL Pinning（证书固定 / 公钥固定）是一种在客户端里“写死”（也可以是自身写死+服务器返回的动态列表）服务器身份的 TLS 增强机制：不只依赖系统信任库（CA 体系），而是额外校验“服务器证书/公钥是不是我预先认识的那一个”。

类型介绍

类型 Pin 的内容 优点 缺点
整证固定​ 叶子证书 DER 哈希 最严格 证书一续签就挂，必须发版
公钥固定（推荐）​ SPKI 的 SHA-256（Base64） 续签同密钥不破，运维友好 实现稍复杂
CA/中间证固定​ 中间 CA 公钥 最稳，适合 CDN 信任范围变大，安全性略降

1. 整证固定（Leaf Certificate Pinning）

原理：客户端保存服务器叶子证书的 DER 编码，计算 SHA-256 哈希，每次 TLS 握手时比对。

优点：最严格，攻击者完全无法伪造。
缺点：证书一续签（哪怕只是重新签发，密钥没换），所有老版本 APP 全部失效。

2. 公钥固定（SPKI Pinning，推荐）

原理：Pin 的不是证书本身，而是证书里的公钥（Subject Public Key Info）。
证书可以换，但只要公钥不变，Pinning 依然有效。

3. 中间 CA 固定（CA Pinning）

原理：Pin 证书链里的中间 CA 公钥。只要中间 CA 不变，叶子证书随便换。
适用场景：
- 使用云厂商 CDN（如 AWS、Cloudflare）
- 证书频繁自动续签（Let’s Encrypt 90 天）

实现：
- 从证书链里取第 1 个或第 2 个证书的 SPKI
- 通常 Pin 中间 CA 的 SPKI，因为叶子证书会频繁换

过检测的方法

  1. LSPosed的各种插件：JustTrustMe、JustMePlush、TrustMeAlready等插件打开。这种不太稳定，能过的也不一定能一次性过。
  2. 使用frida过掉
    用法:frida -U -f packagename -l ./sslpinning.js -no-pause过掉，

下面是脚本内容和解析，选择观看，在遇到问题后对比：

脚本入口：Java.perform(function() { … }) ，在 Java 层运行时注入，Hook 各种 SSL 校验点。

  1. 自定义 TrustManager并实例化：注册一个“接受一切证书”的 TrustManager。checkServerTrusted 空实现：服务端证书永远通过校验。getAcceptedIssuers 返回空数组：不信任任何 CA，但也无所谓，因为校验函数什么都不做。getAcceptedIssuers：返回空数组。
  2. Hook SSLContext.init()：无论 APP 传入什么 TrustManager都替换成自己的。
  3. 按网络库逐个 Hook（广撒网）：
    1. OkHttp 3.x：Hook CertificatePinner.check() ，直接返回不抛出异常。
    2. Appcelerator Titanium：Hook PinningTrustManager.checkServerTrusted，直接返回。
    3. OkHttp 2.x（旧版）：Hook OkHttpClient.setCertificatePinner() ，让 APP 无法设置 Pinner；Hook CertificatePinner.check()，让它直接返回。
    4. WebView：Hook onReceivedSslError() ，调用 proceed() 强制继续加载；Hook onReceivedError() 忽略错误
    5. HttpsURLConnection：Hook setDefaultHostnameVerifier()；Hook setSSLSocketFactory()；Hook setHostnameVerifier()：全部忽略 APP 的设置 。
    6. XUtils（第三方网络库）：注册一个“永远返回 true”的 HostnameVerifier；Hook setSslSocketFactory()；Hook setHostnameVerifier()：强制替换成我们的实现 。
    7. httpclientandroidlib（老式 Apache）：Hook AbstractVerifier.verify()：让它直接返回
    8. Android 7.0+ TrustManagerImpl：Hook verifyChain()：直接返回未校验的证书链；绕过 network_security_config 的 pin-set
    9. OpenSSLSocketImpl（底层 TLS）：Hook verifyCertificateChain()：让它直接返回
    10. TrustKit（第三方 Pinning 库）：Hook OkHostnameVerifier.verify()：让它返回 true
    11. Cronet（Chromium 网络栈：Hook addPublicKeyPins()：让它不添加任何 Pin ；Hook enablePublicKeyPinningBypass…()：强制开启本地信任锚点绕过 。
